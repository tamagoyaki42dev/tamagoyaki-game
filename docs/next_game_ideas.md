## 案①：「AIでゲームを作るシミュレーション」（2026-07-07 発案）

SNS受け皿を一日構築して疲れ果てた夜の雑談から出た着想。**今日一日の体験がそのまま企画書**になった案。

### コンセプト
プレイヤー＝AIを使ってゲームを作る個人開発者。**ゲームを"作る"パートは指示を出すだけ（＝一瞬で終わる・簡単）**。本当にシビアなのは**それ以外の全部**（宣伝・サウンド・ストーリー・スクショ・投稿・モチベ管理・ゼロフォロワーとの戦い）。

### 効いている構造（＝この案の肝）
「ゲームを作るゲーム」は普通、**開発パートが本編**だと期待される。それを裏切って「**開発は指示だけ＝トリビアル、地獄は"それ以外"**」に反転させる。実際に個人開発の渦中にいる人間が作るのでリアリティが本物＝遊んだ人全員が"うっ"となる。

### シビアなパラメータ案（雑談で出た分）
- **フォロワー**：初期0。増えない。たまに1増えてすぐ0に戻る
- **モチベゲージ**：数字ゼロの画面を見るたび減る
- **ポストネタ在庫**：尽きると"ひねり出し"ミニゲームが発生
- **アルゴリズム運**：完璧な動画を作っても再生数は乱数で140か3
- **1日の時間**：有限。開発に振るとマーケが死に、マーケに振ると開発が死ぬ（今日まさに体感したトレードオフ）

### メタの入れ子（宣伝価値）
「AI開発あるあるゲー」を、AI開発あるあるの渦中にいる人間が作る、という入れ子。**この企画の存在自体が、現行作 Perrant の宣伝ネタ（note/X）にもなる**。自分の疲労がそのままゲームデザインに化ける回収。

### なぜこの棚が空いているか（立ち位置の分析）
ゲーム業界に「**作家の内面・業を一人称で描いたメタ作品**」は激レア。Game Dev Story / Game Dev Tycoon 等はあるが、あれは**経営シム**（売上・バグ・締切の管理）であって、バクマン的な"作家の葛藤そのもの"ではない。空いている理由は2つ：
- **人数**：ゲームはチーム制作＝"語る主語（私）"が散る。漫画は一人＝"作家の私"が自然に立つ→メタ作品が生まれやすい
- **コスト**：漫画家は「漫画についての漫画」をペン一本で描けるが、ゲームは自分の業界を茶化すだけでも**フル1本ぶんの制作費**がかかる＝気軽に自分のcraftをネタにできない

→ **ソロ個人開発（＋AI）は、その両方を壊している**：単一の作家性がある（漫画と同じ）＋AIが制作費側を軽くする。つまり「ゲームで作家メタが少ない理由」が、ソロ+AI開発者のところだけ消えている＝空いた棚にちょうど手が届く稀有な立ち位置。

**バクマン論の補足**：作家メタ作品は普通"ヒット後"に作るもの（成功が"語る資格"を与える）。順番としては一作目ヒット前に作るのは逆だが、皮肉なことに「成功後に描く"昔は苦労した"」より「**渦中で描く"今まさに苦しい"**」の方が本物として刺さる可能性がある。バクマンが響くのは作者が本当にそこを通ったから。

## 案⑥：「作業お供の放置ゲー＋ローカルLLMでの会話・ストーリー」（2026-07-11 発案）

開発の裏で回す"作業お供ゲー"を延々探した雑談から出た着想（Chill With You を実際に使いながら「この子とAIで会話できたら」と思ったのが起点）。案⑤「半放置ゲーム」の親戚だが、**AI会話を主機能に据える**点で別枠。

### コンセプト
Chill With You 系の**作業お供／放置ゲー**に、**AIとの会話機能＋ストーリー**を載せる。同席してくれるキャラと、作業の合間に自然に喋れる。

### 効いている構造（＝肝）
- **リモートAPI型のAI物語ゲーは「LLMが別サーバにあって制御が効かない＝もったいない」**という不満が既にある（ユーザー体感）。そこを **ローカルLLM同梱＋ゲーム専用チューニング（LoRA等）** で解く
- **現行 Perrant の設計原則「常時通信なし・完全オフライン」とローカルLLMは同じ方向**。リモート型はその原則に反する＝「もったいない」と感じた正体はこれ。オフライン・API課金ゼロ・同梱、が全部成立する

### いちばん美味しい肝（2026-07-11 追記）
接地の矛先を**ゲーム機構ではなくプレイヤーの実状況に向ける**のがこの案の核。「今何時か」「どれくらい放置してるか」「さっき"これ実装中"と言ったか」等の**リアルな信号に接地**させて喋らせる＝**ここでやっている雑談をそのままゲーム内で**やる体験。例：「ゲーム作ってるけどAIに任せてるから基本暇でしょ」とキャラが実状況にリアクション（＝プレイヤー自身の"ソロ＋AI開発"の構図をキャラが埋める、案①の作家メタと地続き）。
- Chill With You が惜しいのはリアクションが**スクリプト（決め打ち）**で"同席"止まりな点。LLM＋実状況接地で初めて"会話"が生きる
- **売りは「AIキャラ」そのものではなく"あなたの作業セッションの実状態に反応する同席者"**＝Chill With You にもリモートAPI型物語ゲーにも無い空白
- 注意：接地する**本物の信号が無いとランダム相槌botに堕ちる**。「何にリアクションさせるか（放置時間・宣言タスク・時間帯…）」の設計が全て

### 実現可能性（2026-07-11 検討・個人開発で可能か）
結論：**AI部分は個人開発でも十分可能。重いのはその周り（＝普通に1本作る労力）。**
- **モデル自前訓練は不要**：口調はシステムプロンプト＋few-shotで8割。LoRAは味付けでv1では不要
- **配線は既存**：小型モデル（3〜8B量子化＝2〜5GB）を llama.cpp/llama-server で常駐→Godot から localhost HTTP で叩く。完全オフラインのまま成立。GDExtension 系実装もあり
- **"実状況リアクション"の核はただのプログラム**：放置時間・時刻・タスク文字列をプロンプトに詰めるだけ＝GDScriptで書ける。ML不要
- **壁**：配布サイズ＋数GB／GPU無しPCで遅い（→小型モデル＋トークンstream表示"考え中"演出で殺す、上級者は自前Ollama/API接続の逃げ道）／小型は賢さの天井低いが**この用途は超寛容**（短い相槌に深い推論不要＝小型の得意ゾーン）／暴走は短文＋ガードレールで抑制
- **v1で沈む地雷3つ（禁止）**：①モデル自前訓練 ②LLMにゲーム数値・進行を確実操作させる ③長編ストーリーをLLM生成させる
- **v1の姿**：ローカル小型モデル＋人格プロンプト＋実状況の文脈注入＋短い相槌。数週間のプロトで"喋る同席者"まで到達可能、刺さるか検証はそこから
