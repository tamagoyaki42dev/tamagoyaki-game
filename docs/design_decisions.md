# 設計判断ログ（触ると死ぬ配線）

## これは何・どう使う

数値・現仕様の正典は**コードと spec**。このファイルは**判断本体を持たない**——「**どの配線を何気なく変えると設計が壊れるか＋なぜ守るか**」だけを置く。事実（どう動くか）は spec に書く。ここに二重で書かない（そうしないと「一つ直すと何箇所も」が再発する）。

### 更新ルール
- 既存メカニクスの**意味・トリガー・発動条件**を新しく確定/変更したら、その配線を**1エントリ足す**
- 各エントリは3点だけ：**配線（どこ＝file＋一言）／変えると壊れる（何をすると事故か）／なぜ守る（specに書けない設計意図）**
- **判断の"事実"は書かない**（＝specへのポインタで済ませる）。ここに書くのは「守る理由」と「やったら事故る操作」
- **網羅しない。** 「何気なく変えると死ぬ」配線だけ。肥大すると照合対象が埋もれ、regen事故と同じ穴に落ちる

### 照合ルール（検証エージェント・前提照合犬）
- **土台ファイル**（`battle_manager.gd` / `character_data.gd` / `enemy_generator.gd` / `enemy_data.gd` / `test_battle_sim.gd`）の編集、またはバランス・戦闘ロジックの相談時、このリストと矛盾しないか照合し、触れていたら警告する
- 数値が正しいかの検算は別（数値照合犬＝balance-verify のシム検算）。ここは「判断が矛盾してないか」専門

## 配線リスト

### 回復トリガー（原作準拠・2026-07-04 確定）
- **配線**：`battle_spec.md` 敵/味方の回復発動条件（敵＝プレイヤーのローテ時のみ／味方＝後列で毎ターン）
- **変えると壊れる**：敵回復を毎ターンに戻す・敵ごとにトリガーをバラす・味方と敵のトリガーを揃える
- **なぜ守る**：原作『7〜モールモースの騎兵隊〜』の「ローテすると回復する敵」＝ローテ抑止装置。敵ローテ時／味方毎ターンの**非対称が仕様**。揃えると原作準拠と戦略性が死ぬ

### 敵 regen の意味＝ローテ罰
- **配線**：`enemy_spec.md` 各敵の self_regen 値、B2設計メモ
- **変えると壊れる**：regen を「発動しないから無駄」と消す/弱める
- **なぜ守る**：regen は「ローテすると回復するからローテするな＝STAY推奨」の抑止装置。**発動しない＝プレイヤーが正解を選んでる＝正常**（発動回数で価値を測るな）。壁が緩いなら regen でなく HP 等**別ステで締める**

### 敵の強さの主表現＝仕掛け ＞ 額面
- **配線**：`enemy_spec.md` / `unit_spec.md` のバランス方針
- **変えると壊れる**：難度調整で HP/ATK を膨張させる
- **なぜ守る**：強さは regen・思考タイプ・行動サイクルの仕掛けで出す。額面膨張はダルさに化ける（最終手段）

### ドキュメントとコードの二重管理禁止
- **配線**：全 docs
- **変えると壊れる**：数値・現仕様を spec とコードの両方に書く
- **なぜ守る**：更新漏れ・陳腐化の温床。数値はコードが正典、doc は判断（このファイル）だけ
