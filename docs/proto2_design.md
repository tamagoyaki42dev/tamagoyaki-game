## 個体値＋偏差（分散）システム（着想・2026-07-01）

proto2以降。味方の特徴＋総合ポイント式の上に乗せる。

- 狙い：①**個体値（ポケモンのIV的な per-個体の固定差）**＝個体ごとに違うステ＝フィール再現・愛着・世代継承の土台 ②**偏差/分散式**＝みんな似たステになると面白くないので、たまにアーキタイプを外す個体を出す（HPの低い戦士／攻撃の高いヴァルキリーがいてもいい）
- **設計指針（重要）：個体値は総合ポイント式の「再配分」として作る**。同じ総量を別配分で使った個体にすれば、アーキタイプを崩しても点が帯（81〜91）に残る＝非支配・balance が保たれる。「攻の高いヴァル」は間接/HPを削って近接に回した結果＝フェアな尖り
- 2段構成：**①総量保存の再配分**（基本の個体差）＋**②たまに大きく振れる裾**（偏差・意外性）。現在の `character_data.gd from_job` の `randf_range(0.8,1.2)` フラット±20%は「全ステ独立・均一」で尖った個体が出にくい＝これを置き換える
- [[手続き生成系の2原則]]（分布は解析的に出す・raw全ダンプ禁止）と直結。世代継承＝採点済みパーツの合成、の前段

## 【土台・必読】手続き生成系（ローグライク・世代継承）を着手する前に置く2原則（方針決定・2026-06-29）

- 背景：乱数生成のあるシステムを**総当たりシミュで balance しようとすると状態空間が爆発**し、出力も思考も食い尽くす（シミュのログ爆発で Claude が無言停止した事件＝その100倍版の予告編）。これを踏まないための土台を、生成系に入る前に置く
- **原則1：生成と検査を分ける。** 生成＝ヘッドレスでデータをファイルに書く／検査＝Claude は集計サマリと単一 seed だけ読む。**raw な全文ダンプを応答に展開させない**（balance-verify スキルの「出力規律」と同根）
- **原則2：乱数は実験でなく数式で畳む。** プリミティブの語彙 → 閉じた EV → スコア。balance は「100試行回してログを見る」でなく**計算で分かる**状態にする。シミュは「式が合ってるかのスポット検査」に格下げ＝出力は小さいまま
- これが効く帰結：①シミュが主役から降りる（出力小） ②seed で異常を1ケースに畳める（洪水でなく1点デバッグ） ③世代継承＝採点済みパーツの合成（`unit_spec.md` 総合ポイント式の延長。系譜全回し不要、分布は解析的に出る）
- **逆に：この土台を作る前に「とりあえず生成してシミュで見る」をやると死ぬ。** 生成系こそ Claude の得意分野（ルール＋seed で閉じる・解析EV・自動検証＝`claude_leverage_strategy` の本丸）だが、それは土台があってこそ

## 戦闘の深みの中核＝「敵の行動乱数」を編成の網羅率で覆う構造（方針決定・2026-06-28）

- 敵の行動を確定サイクルから**確率提示**へ（例：攻撃60%/溜め40%。オッズは開示、結果は引くまで不明）。ローテ/ステイが確率の賭けになる。入力は増やさず既存の「行動タイプ開示＋ローテ/ステイ」を深めるだけ
- 揃った編成は確率の全面を覆って死なない／欠けた編成は穴に乱数が刺さって死ぬ＝**負けが「どの駒が足りないか」の診断になる**。「投資が形になる」の核心、次回作コレクション構想と地続き
- 思考パターンは**物量で複数セット**用意。さらに行動パターンを**手続き生成＋EV化**して難易度スコアリング
- **2軸スコア**：EV＝倒せる範囲かの担保／分散（スパイク）＝編成の網羅率をどれだけ要求するか。既存スタット生成の「必ず倒せる範囲＋極振り個体」と同じ二段構えを行動パターンに横展開
- 行動を**プリミティブの語彙**（通常・溜め・連撃・狙い変更・石化・防御…）に分解すれば各EVは閉じた式で算出でき生成時に難易度即計算できる
- **敵EV難易度 × 味方総合ポイント＝無限モードのマッチメイク中核**（`unit_spec.md` のキャラ総合ポイント式と対になる）
- **却下：挑発（アクティブ/パッシブ）**。入力帯域がほぼ無くアクティブ指定の隙がない＋「乱数を操作で御す」方向自体が本作の魂（御せない乱数こそ怖い・面白い）と逆行する

## 攻めのカタルシス＝「必殺ボタン（連携発動）」1個を追加する方向（暫定決定・2026-06-28／具体像は未確定）

詳細議論は `devlog/2026-06-28.md`。

- 押すと前列が対象に総攻撃。**乗っている仕込みの数だけダメージが掛け算で膨らむ**（剥がし×／石化×1.5／補助＋／クリチャ×N／前列の手数）。散らばった仕込みを一点に集約して爆発させるBalatro的快感＝「数字がデカくなる気持ちよさ」の集約先
- 仕込みは壊れやすい（クリチャ＝被弾で消失／石化・剥がし＝ローテで戻る／補助＝使用で消失）→**同一ターンにピークで揃えて撃つ**＝勝ちも負けも自分の組み立て次第＝納得性が保たれる
- **設計原則（確定）**：
  1. 乱数は「覆う」もので「当てる」ものにしない（覆える乱数の負け＝育成ミス＝納得／当てる乱数の負け＝ガチャ負け＝不可）
  2. 入力は「足す改造」だけ許す。「引く改造」（弱い列が前線に立つ宿命からプレイヤーを逃がす改造）は守りの緊張を殺すので禁止
  3. 入力増加はギリギリ1個まで。それ以上は絶対に増やさない。だからその1個は前提を覆すほど面白くないといけない
- **却下：ローテ方向トグル（前回り/後ろ回り）**。連携の組み立ては可能になるが、弱い列（回復役）を永久に前へ出さず回避できてしまう＝「弱い列を凌ぐ」守りの核を殺す＝「引く改造」
- **創造性は「ボタンの存在」でなく「ボタンが何を掛け算するか（倍率の文法）」に注ぐ**。器は無難、中身を尖らせる
- **任意と必須は難易度軸で両立**：ぬるい敵は無視で勝てる（編成計算を外さない）／高EVの敵は連携必須（前提が覆る）。敵EV生成と直結

## リリース後にグラフィック一挙改善パスを組む（方針決定・2026-07-04）

プロト1は現状の見た目（Kenney mini＋clay shader）のまま完走する。既視感を削る施策には着手せず、**リリース後にまとめて時間を取って一挙に検証する**方針に決定（backlogに置くと「アート欄」が肥大し直近タスクが埋もれるため、ここに集約）。

- 会話ログ（2026-07-04）での絞り込み：静止画（タイトル画面等）で個性が伝わるのは③ハッチング影／④プロポーション変形／①LUTの3つ（動きに依存しない効果のため）。⑤頂点ボイルは動いてこそ伝わる効果で、静止画（タイトル画面用途）には向かない
- タイトル画面のキャラ表示個性づけとして④プロポーション変形（チビ化スカッシュ）を先行候補に決定。ゲーム内UIオフセット（武器・リング・HPバー）に触れずタイトル画面のキャラ1体だけで検証可能
- **アートで一点だけ全振りするなら⑤頂点ボイル（2026-07-04 決定）。** 「たまごやき」という名称自体に深い意味はない（ユーザー確認済み）が、頂点ボイルの手作り感と結びつけて差別化の核にすることに合意。マーケ導線がSNS縦動画中心（[[sns_vertical_video_workflow]]）＝動きが主戦場のため、静止画に映らない弱点は実運用上ネックにならない

狙いは共通＝「KayKit/Kenney をそのまま出すと“またこれか”になる。塗りとトーンで“どこ製か分からない”状態にする」。コードで届く範囲のみ。レバレッジ順。**メッシュ（形）は既視感の原因じゃない。原因は塗りと画面全体のトーン。** どれも作風層なので KayKit 乗り換え後も生きる。

- [ ] **① 全画面パレットLUT（カラーグレーディング）** ★最有力・低リスク
  - 何：画面全体を署名パレットに通して色を統一（WorldEnvironment `adjustment_color_correction` に1枚LUT）
  - なぜ効く：CC0がゲーム間で同じ顔に見えるのは全員デフォルトalbedoをデフォルトトーンマップで出すから。固定パレットに通すと素材の出自が消える（Sable / Lethal Company 方式）
  - 労力：小（post 1枚）。スパイク5分で白黒つく
- [ ] **② 紙/粘土グレイン＋ポスタライズ**
  - 何：全画面に微細グレイン＋色段階の量子化を重ねる
  - なぜ効く：デジタル清潔感（CC0最大の手がかり）を消し「印刷/塗られた物」に見せる。粘土おもちゃブランド一致
  - 労力：小（既存の輪郭postに足せる）。リスク＝盛りすぎると泥化（`@export`で控えめデフォルト）
- [ ] **③ ハーフトーン/ハッチング影**
  - 何：clay shaderの影部分をフラット塗りでなく網点/ハッチングで埋める
  - なぜ効く：「標準トゥーン」感を脱し強い作風署名になる（Obra Dinn / 漫画ハッチ系）。やる人が少ない
  - 労力：中（clay shaderの `light()` に追記）
- [ ] **④ プロポーション変形（チビ化スカッシュ）** ※タイトル画面個性づけの先行候補（2026-07-04）
  - 何：全キャラにspawn時「頭大きめ・胴小さめ」の一律スケールを噛ませる
  - なぜ効く：コードで唯一“形の見覚え”を変えられる手。KayKitがKayKitに見えなくなる。静止画でも即伝わる（シルエット変化）
  - 労力：小（spawn時transform）。リスク＝武器/リング/HPバーのオフセット再調整が要るかも（タイトル画面のみなら不要）
- [ ] **⑤ 頂点ボイル（クレイアニメ風の揺れ）** ※効果最大だが最後・静止画には無効
  - 何：頂点を毎数フレームだけ微小ジッタ＝手作り/粘土の「ボイル」感
  - なぜ効く：「手作り」署名最強・たまごやきブランド直結。ただし1枚の静止画には映らない＝動いてる場面（戦闘・デモ）向け
  - 労力：中（vertex shader）。リスク高＝振り切るとメッシュ崩壊（`@export`必須・他で物足りなくなってから）

- [ ] **顔差し替えで「モーション流用＋個性」を出す（2026-06-30 着想・最終形未確定）**
  - 狙い：胴・スケルトン・アニメは固定で流用、頭/顔だけ替えて個体差を出す。世代継承（顔を継ぐ）と地続き
  - 仕組み：このローポリの頭は変形しない剛体プロップ＝頭ボーンに別メッシュ/テクスチャをぶら下げ元頭を隠すだけ。武器アタッチ（`_attach_weapon`／`arm-right`ボーン）と同型。まず頭ボーン名を確認（`head`系のはず）
  - 3段（独立して選べる）：
    - **Tier1：顔をテクスチャ/Decalで差す**（頭メッシュは据え置き）。リスクほぼゼロ・粘土おもちゃ＝顔は印刷とブランド一致・継承で無限に安く出せる ←最小労力で狙い達成
    - Tier2：同系統パック（KayKitモジュラー）内の別頭をボーン差し替え。原点が揃ってて低リスク
    - Tier3：他パックの顔メッシュを移植。可能だが①原点/回転/スケール辞書（`_HEAD_OFFSETS`等・武器と同型）②首の継ぎ目隠し（襟/兜）が要る
  - 落とし穴：別ソース顔は貼り付け感（ポリ/テクセル密度差）が出る→**作風層（clay＋上記①LUT）に通すと1個の素材に見える**。顔移植と作風層はセットで成立

## 最終形はキャラ基盤を KayKit に寄せる（方針決定済み・2026-06-25）

女性キャラが欲しい場合は髪パーツを自分で Blender 制作するのが最良、という結論。

- KayKit Adventurers（Kay Lousberg / CC0・$0ティアあり）。ファンタジーRPG native（Mage/Knight/Barbarian/Rogue/Ranger＋武器・帽子・杖同梱）でジャンル適合が高い。modular でパーツ着せ替え可。グラデアトラスで色替えも Blender 不要
- **乗り換え可否の最大の関門：アニメ名が現行コード依存（`idle` / `attack-melee-right` / `attack-melee-left` / `die`）と一致するか。不一致ならアニメ呼び出しコードの差し替えが必要**
- 進め方：Free版を落として Mage 1体スパイク → アニメ名・見栄え・色替えを確認してから全替え判断
- Kenney mini と混在禁止（やるなら全部 KayKit に寄せる）
- プロト1はこのまま Kenney mini で完走する（今は寄り道しない）
- **既視感（「またこれか」）懸念は素材パック選びでなく作風層シェーダー（上記「リリース後にグラフィック一挙改善パスを組む」）で解くと決定（2026-06-29）。** 作風層は素材を問わず被せられるので、KayKit/Kenney どちらに転んでも既視感対策は効く＝この判断と独立
