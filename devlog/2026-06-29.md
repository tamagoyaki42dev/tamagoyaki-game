# Devlog 2026-06-29

## 作風（アートディレクション）の検討

KayKit に寄せる方針（2026-06-25 決定）に対し「KayKit でいいのか」の悩みがぶり返した。掘ったら本質は見栄えの好みではなく「**KayKit Adventurers はインディーで多用される顔＝物量で押す本作だと量産するほど『またこれか』の既視感が増える**」という**ブランドの問題**だった。

### 整理の流れ
- 既視感の発生源は**メッシュ（形）ではなく「デフォルトの塗り」**（標準ライティング＋標準パレット＋標準プロポーション）。色替えだけでは shading・silhouette が残ってバレる
- 抜け道＝**自分だけのレンダリング作風（作風層シェーダー）を1枚被せる**。素材集を問わず被せられるので KayKit/Kenney 判断と独立して既視感を潰せる。しかも shader＋post は Claude の最も強い領域
- 作風の中身は「無難なトゥーン」に落ちないよう、**game の外側（スタジオ名・感情の核・題材）に結びつけて**決めた：
  - たまごやき＝手作り・あたたかい
  - 世代継承＝愛着・蓄積（棚に並ぶフィギュア感）
  - 拠点整備＝素材加工・工場化（素材の質感そのもの）
  - → 3つとも同じ方向を指す＝**「マット粘土／塗装おもちゃの箱庭」**

### 確定したこと
- 狙う作風：**マット塗装のおもちゃ／粘土ジオラマ＋ティルトシフト**（「絵に見せる」王道トゥーンでなく「作りものに見せる」）
- スコープ外：毛糸フェルトの縫い目・毛羽（shader でなくアート資産＝コード担当外）
- マット粘土は「土のバケモン化」の全原因の逆＝クラフトで一番形が崩れない安全地帯
- 保険：調整値を全部 `@export` 化＝Claude は控えめデフォルトの調整盤を納品／ユーザーが見ながら回す
- **次アクション：現行 Kenney mini 戦闘画面に shader 一式を乗せるスパイク → 目視で white（採用）/black（撤退）判定。** 詳細は `docs/backlog.md` アート欄

## noteネタ

- **「Claude にやらせると原型留めてない土のバケモンができそう」** — クラフト作風（マット粘土）を Claude に任せる是非を詰めていたとき、ユーザーが漏らした一言。表現が秀逸すぎた。実際マット粘土はバケモン化リスクが一番低い端で、しかも `@export` 調整盤にすればツマミはユーザーが握るので構造的に泥にはならない…のだが、「土のバケモン」というワードの破壊力が全部もっていった。スパイクで本当に泥が出たら正式に noteネタ昇格。

- **シミュのログ爆発で Claude が無言で死んだ事件** — 別セッションで3戦バランス検証シミュを回したら、`Claude's response exceeded the 32000 output token maximum` というエラーが出てそのまま応答停止。最初ユーザーは「これ何？」と聞いてきて、こちらは「僕がしゃべりすぎただけ、気にしないで」とトンチンカンな回答をした（このチャットの token 上限だと思い込んだ）。実際は**シミュが per-turn ログを stdout に垂れ流し → K=100試行ぶんの巨大ログを Claude が応答に展開しようとして上限超過 → 打ち切られたターンが完了できず無言で停止**、という別物だった。教訓：シミュ系は「人間が読む詳細ログ」と「集計サマリ」を最初から分けないと、AI が自分の出力で窒息する。backlog に「出力規律」として明文化。AI に大量データを処理させる時代ならではの詰まり方で、ちょっと面白い。
  - **オチ**：この日ユーザーは「時間がないから早くトークンを使い切りたい」と、シミュと SE 実装を**並列で同時に回していた**。結果、シミュが爆発して一瞬でトークンが溶けた＝「早く使い切りたい」願いが*クラッシュという最悪の形で*叶った。しかもシミュ暴発は token 的に最悪（巨大出力を満額読み込んで→打ち切り→成果ゼロ）。教訓2：時間ない日の並列実行は良い戦略だが、生成・シミュ系を混ぜると爆発の取り分がデカい。混ぜるなら「重い1本＋軽い1本」。
