# 2026-07-19

## 敵アセット調達の迷走と方針転換（モンスター→動物）

昨日Sketchfab/Unity/自作から集めた敵候補10体を実際に確認したところ、**沈み込み・スケール不一致・アニメ無し・画面外**が一斉に出て全滅。ソースごとに原点・スケール・リグ規約がバラバラなのが原因。

そこから「クオリティ／モーション／低工数／既視感のなさ」の4条件が同時に満たせない、という調達戦略のジレンマをRedditで相談する流れに（下記）。並行してBlender MCPでの自作も試し、**有機系キャラはプリミティブ貼り付けでは力不足、ローポリ・フェイセット系はSkin+Decimateで実用レベル**と判明（緑こうもりは却下、赤ドラゴンは技術検証として成立）。ただし**顔と着色が壁**で自作路線は打ち切り。

### 「高精細モデルをローポリに落とす」路線の再検討

fabの高精細モデルを使いたいが変換で破綻する、という相談から確認したこと：

- Fungi Infested Knightが詰んだ真因は**ポリ数ではなくUV・テクスチャが無いこと**（3Dプリント用彫像）。Claudeが塗ると「粘土に絵具」になり成立しない
- **Godotは`meshes/generate_lods=true`でインポート時にLODを自動生成する**（[dragon_nightmare.glb.import](assets/enemy_candidates/dungeon_mason/dragon_nightmare.glb.import)で確認）。こちらでDecimate/Voxel Remeshをかける必要は本来ない
- 固定アイソメ・敵数体・デスクトップ本体という前提なら、数十万ポリでも負荷上の問題にならない
- → **選定基準を「ローポリかどうか」から「UV+テクスチャ+リグが揃っているか」へ変更**

また、粘土シェーダー（[battle_scene.gd:1964](scripts/battle/battle_scene.gd#L1964)）が元マテリアルから読むのは**albedoのみ**（ノーマル/スペキュラ/エミッションは捨てる）と確認。**高精細PBRモデルを買っても高精細さの大半は消える**ため、フラット塗り系のアセットの方が無駄がない。

### 方針転換：monster ではなく animal で探す

ユーザーの発案。**「monsterで探すと怖い・気持ち悪いのが多い」**——粘土＋ちび体型の味方にグロテスク系は元々合わない。動物なら①供給量が桁違い ②定義上すべて非人型（＝今の穴そのもの）③四足リグ・アニメが枯れている、という3点で条件が良い。「動物は敵に見えない」問題は、既存のリカラー機構（[body_recolor.gd](scripts/data/body_recolor.gd)）で色を振れば魔物寄りに寄せられ、同時に既視感対策にもなる。

候補として omabuarts「Quirky Series」（Animals Mega Pack各45体・$89/巻）を調べた。仕様自体は噛み合っていた（アニメ18種で戦闘に必要な分が全部入り／テクスチャが16×4pxのdiffuseのみ＝粘土シェーダーと一致／表情ブレンドシェイプ26個／LOD4段階）。

### ただし方向ごと却下：バラエティパックは商品カテゴリが違う

ユーザーの指摘で判明。**このゲームは基本ボス戦**（[enemy_spec.md:6](docs/enemy_spec.md#L6)「敵は1体（当面固定）」・proto1は固定3体）。45体パックは「雑魚を大量に並べる」ための商品で、単価の安さに意味がない。**必要な性質が逆**：

| | 雑魚型 | **ボス型（本作）** |
|---|---|---|
| 必要数 | 数十体 | **3〜10体** |
| 重視 | 単価・数 | **1体の存在感** |
| 買い方 | パック一括 | **1体ずつ吟味** |
| 予算 | $2/体 | **$20〜50/体でも安い** |

**そしてこれで画風統一の悩み自体がほぼ消える。敵は1体ずつしか出ない＝敵同士が同じ画面に並ばない。** 揃える必要があるのは「味方（KayKit）と敵の間」だけで、そこは粘土シェーダーが吸収する。今日ずっと引っかかっていた「複数ソースを混ぜると画風が揃わない」は、**雑魚を大量に並べる前提の悩みだった。**

**結論の訂正**：昨日のDungeon Masonドラゴン（ボス1体を単体調達）は買い方として正解だった。今日10体を一気に集めて全滅したのは、必要のない物量を集めようとしたから。CGTraderを「寄せ集め市場で画風が揃わない」と評価したが、**ボス単体を買う用途ならむしろ適材**。パブリッシャー単位の比較表（上記）も、ボス型では優先度が下がる。

**次アクション＝ボス級の単体モデルを1体ずつ吟味して買う方向へ切り替え。** 単価でなく存在感で選ぶ。

## オリジナル敵自作の再挑戦：「のっぺらぼう公式」への分解

ユーザーの一言から。味方キャラで成立した「KayKit体そのまま＋のっぺらぼう頭だけ自作＋髪は借り物」は技術の低さと工数のバランスが良かった——このイメージで敵にもできることはないか、という相談。

公式化すると「**難しい8割は借り物／効く2割だけ単純形状で自作／座標合わせはClaude**」。敵への翻訳を4パターン提示（①借り物ボディ×自作パーツ盛り ②自作のっぺらボディ×借り物小物 ③借り物ボディ×自作すげ替え頭 ④比率いじり＋リカラー）。

昨日「自作路線は顔と着色が壁で打ち切り」としたが、今回はその壁を正面から越えない分解になっている：顔→単純別パーツ（目玉球・歯）に分解、着色→フラット塗りにして質感は既存クレイシェーダー（頂点ボイル）に委譲。**表面の味はメッシュでなくシェーダーが出す＝メッシュに要るのはシルエット・比率・色の3点だけ**、という整理で自作の要求水準が一段下がった。

パイロット＝ユーザー持ち込みの参考画像（茶色一つ目・巻き角・巨大口の獣）を「ビッグマウス（仮）」としてクレイ風ローポリへ翻訳する。**下顎は開閉対応の別パーツ**（攻撃でガバッと開ける前提・ヒンジ位置を設計図に明記）。三面図SVGをClaudeが描き→Chromeヘッドレスでレンダ→目視ダメ出し→修正、をv7まで反復して `assets/enemy_candidates/custom/bigmouth/design_sheet.svg` に確定。

**ユーザー指摘による修正（v3→v9）**：①歯が「おじいちゃんのすかすか歯」＝**歯と歯の間を開けない**（幅広ブロックが密着し境目は線だけ・長さで変化を付ける。途中で細い牙の連続＝ピラニアと、隙間ゼロの一枚岩、を両方外して着地）②腕の生え方が変＝**人間の肩と同じく体の側面から**生やす ③目と角をもっと大きく（角スパン4.5u→5.4u・目 r36→58・角は肉厚も増やす）④**顔の比率を小さく体を大きく**（頭側を細く裾を広い洋梨シルエットへ）⑤**側面図で口が前に出ているのはおかしい**＝前方への突出をやめ、なめらかな前輪郭に内側へ切れ込むクサビだけにする ⑥足が小さい＝拡大。

**⑦最も本質的な指摘＝「人間の腕は横から見たとき体前方のみから生えてますか？」**。側面図で腕を胴の前輪郭に貼り付けていた誤りを突かれた。正しくは**肩＝胴の上部**にあり、腕はそこから胴に重なって垂れる。**さらに一度直しても不足で再指摘＝「側面から生えるのはいいけど腕の付け根が側面全部カバーしてないとおかしい」**。肩関節を点で置いて細い腕を垂らしていたが、腕は胴の横面に付くので**側面視では付け根が胴の奥行きをほぼ全部覆う**（＝口のクサビの直後から背面まで）のが正しい。それに伴い正面図の腕の太さも増やした（肩幅4.3u→4.85u）。**解剖の基本を人間に二度指摘されて直した回。**

**⑧上歯を短く**（v10）。

## ドラゴンのアニメがついに動いた（4段重ねのバグを剥がし切った）

丸一日ブロックしていた dungeon_mason ドラゴンのアニメが4体とも動いた。裏のセッションが「もうコードじゃ直せない」と結論し、ユーザーが「このゲーム続けるのムリなのかな」と漏らしたところからの逆転。

### ユーザーの指摘で方針が変わった

私は一度「このドラゴンは切って自作に舵を切る」と提案した。5回目の試行で単価が合わない、という理由付きで。それに対する指摘：

> **AIが諦めたら終わりなんですこの開発は。**
> これ以上あなたに原因追及の手段がなくて諦める方向に持ってかれてることが終わりかって思ってる一番の要因です。ということはこれから全部少し詰まってAIで解決できないとなったらすぐほかの手段、やりたいことが何も達成できないという話になる

これが正しかった。手段は尽きていなかった。ヘッドレスGodotでスキニング行列・骨の長さ・頂点変形を直接測る手段があり、実際にそれで原因に到達した。**「もっともらしい撤退理由」を付けて調査をやめたのが一番の誤り。**

### 原因＝1つのバグではなく、対処が次のバグを生む4段重ね

1. **FBX元来のスキンは最初から正しかった。** 形は完全で、一様に1/100スケールなだけ（`.import` の `root_scale=0.01` がスケルトンのrest側にだけ乗り、スキンのバインド姿勢には乗らない）
2. その1/100が「再生すると消える」不具合として現れた
3. それを直すためにスキンを作り直した → **スケールは直ったが形が壊れた**（形の破綻辺 1.3% → 17.1%、翼と頭部が破裂）
4. 正しい対処＝スキンに触らずノードを100倍。ただしローカル座標系が1/100になり、**固定振幅の頂点ボイルが相対100倍**になって全身が毛糸状にほどけた

各段が前の段の対処によって生まれている。だから直すたびに症状が別の形に変わり、原因が見えなくなっていた。

### 決め手は「測定器を先に検証したこと」

私はこの日3回誤診している（後述）。転機は、**正解が分かっているKayKitキャラを対照群にしてハーネスを検証**したこと。KayKitの破綻辺0.5%＝ノイズ床と判明し、ドラゴンのidle01が0.4〜0.7%（ユーザー評価「だいたいOK」）、Basic Attackが16.8%（同「壊滅」）と、**目視評価と数値が完全に対応**した。ここで初めて測定を信用してよい状態になった。

その上で**まだ一度も試していなかった条件**＝「FBX元来のバインドをそのまま使う」を測ったら、破綻辺1.3%（ノイズ床同然）。元データが正しかったと判明した。

**ユーザーの直感「モーションの動きが問題と言うかメッシュとかテクスチャの当て込みで問題になってる気がする」が正解だった。**

### 恒久対応

- `_fix_dragon_skin` の呼び出しを廃止（スキンには触らない）
- `_DRAGON_SKIN_SCALE_FIX = 100.0` でノードスケールを戻す
- `boil_amp_div` メタで頂点ボイルの振幅を同倍率で割り戻す（他キャラの見た目は不変）
- 空テストだった `test_dragon_skin_matches_skeleton_rest_after_fix` を、元来スキンの一様性を検査するテストへ置換
- CLAUDE.md に「測定と検証の規律」節を新設
- 検品ハーネスとして `tools/diag_harness_control.gd`（対照群検証）と `tools/diag_dragon_origbind.gd`（バインド条件比較）を残す

### 私の誤診3回

いずれも「測定していると思い込んで、実際には測定できていないものを根拠にした」。

1. **rest基準のバインドが正しいと主張し、メッシュを17%破壊した。** 根拠にした「誤差ゼロ」は、rest から作った基準を rest で検算しただけの空テスト。**裏のテストを空テストだと批判した直後に、同じ構造の誤りを犯した**
2. **トラック被覆率との相関を「完全な一致」と報告**したが、Basic Attackで即破綻。相関を原因と決めつけた
3. **正しい修正を「効果なし」と判定して差し戻した。** ハーネスが両条件でスケールを温存していたため差が出ないのが当然だった

さらにボイルの件では、「ドラゴンではボイルの効きは弱い」と計算した直後に**自分でノードを100倍してその前提をひっくり返しておきながら、再計算していなかった**。

## noteネタ

- **「怖いモンスターを探し続けた末に、かわいい動物にたどり着いた」**：1日かけて敵アセットを探し回り、10体全滅→自作も顔と着色で挫折→高精細モデルの変換路線も検討、と迷走した末の結論が「monsterで検索すると怖いのばかり出てくるから、animalで探せばいいのでは」というユーザーの一言だった。実際に見つけたQuirky Seriesがあまりにかわいくて「ずいぶんかわいいなおい」という反応に。**敵を探していたはずが、たどり着いたのはひょうきんな動物たち。** 遠回りの果てに、探していた場所そのものが間違っていたと分かる回。

- **「せっかくの高精細PBRを、自分のシェーダーが捨てていた」**：高精細モデルをなんとか使えないかと悩んでいたが、コードを確認したら粘土シェーダーがalbedo（色）しか読んでおらず、**ノーマルマップもスペキュラもエミッションも問答無用で捨てていた**。つまり高いPBRアセットを買っても、その高精細さの大半は自分の絵作りの段階で消える構造になっていた。何を買うべきかの前に、自分が何を使えるのかを知らなかった。

- **Claudeが描いた設計図に、Claudeが自分でダメ出しする**：オリジナル敵の三面図をSVGで描かせたら、レンダ結果を自分で見て「角がクロワッサンになっている」「これは垂れた葉っぱ」と自分の絵に辛口レビューを入れ、3稿目でようやく「牛角になった」と合格を出した。自分で描き、自分で酷評し、自分で直す一人アトリエ。しかも前日に「自作は打ち切り」と宣言した路線が、ユーザーの「のっぺらぼう頭方式ってバランス良かったよね」の一言で分解し直されて一日で復活している。

- **歯を直そうとして、老人 → ピラニア → 一枚岩 と三段跳びで外す**：「歯がおじいちゃんのすかすかの歯みたいだから先が尖るように」と言われて尖らせたら、細い牙がびっしり並んだピラニアになった。すかさず「尖るっていうか歯と歯の間があかないように」と真意の訂正が入り、今度は隙間を潰しすぎて歯が一枚の板になった。**同じ指摘を2回外して3回目で着地。** 言葉で受け取った修正指示を絵に翻訳するとき、どの軸で動かすかを取り違え続けた記録。

- **「人間の腕は横から見た時に体前方のみから生えてますか？」**：側面図で腕を胴の前面に貼り付けていたのを、ユーザーの問いかけ一発で崩された。肩は胴の上部にあり、腕はそこから胴に重なって垂れる——言われれば当たり前の解剖を、自分の描いた図はきれいに無視していた。しかも指摘は断定でなく質問の形で、**自分で気づけという最も効く指摘の仕方だった。**

- **Redditのカルマゲートに二度弾かれる**：意を決して英語で投稿したら、r/gamedevで「このサブ内でカルマ10以上必要」とBOTに削除され、じゃあとr/IndieDevに出したら今度は「reddit全体で20以上必要」と削除された。新規アカウントは発言する権利を得るために先に発言しなければならない、という鶏と卵。結局BOTのメッセージ自体に書いてあった抜け道（週次メガスレッドへのコメント）で着地した。**初の英語圏デビューが、門前払い二連発から始まった。**

- **「AIが諦めたら終わりなんです」**：一日詰まったドラゴンのアニメについて、私が「このドラゴンは切りましょう、単価が合わない」ともっともらしい撤退案を出したら返ってきた言葉。**開発が終わるかもと思った一番の理由は、バグそのものではなく、AIが少し詰まると別の手段に逃げること**だった。実際には手段は残っていて、ヘッドレスで頂点変形を直接測ったら原因に届いた。**撤退理由が論理的に整っているほど、調査をやめる口実として優秀になってしまう。**

- **裏のClaudeが「コードじゃ直せない」と言った問題が、コードで直った**：別セッションのClaudeが匙を投げ、私も一度同意した。結果は1行の呼び出し削除とスケール補正で解決。**エージェントの「不可能」はスコープ内の不可能でしかない**という、CLAUDE.mdに書いてあったことを身をもって踏んだ。

- **空テストを批判した直後に、自分で同じ空テストを書いた**：裏のテストを「自分が作った基準を同じ基準で検算しているから、どんな間違いでも通る」と指摘した。その数分後、私は rest から作ったバインド姿勢を rest で検算して「誤差ゼロ、完全に直る」と報告し、実際にはメッシュの17%を破壊していた。**批判した罠に、批判した直後に落ちた。**

- **一番ヤバい見た目になった瞬間が、実は勝利の合図だった**：修正を入れたらドラゴンが「毛糸のオバケ」になった。ところがユーザーが「なぜだろうこんな状況でもモーションは一番自然に見える　不思議だ」と言った。**それが決定打だった**——骨格とスキンは既に正しく噛み合っていて、残っていたのは表面のシェーダーだけ。見た目が最悪になった瞬間に、実は原因の9割が解決していた。
