# バランス検証フロー

このスキルは**2段の検証**を持つ：**①前提照合**（作業前・`docs/design_decisions.md` の「触ると死ぬ配線」と突き合わせ、既存の設計判断を壊さないか）＋**②数値照合**（結論後・シム検算、数値が正しいか）。別々の犬なので両方走らせる。

## 作業前（①前提照合）

- **`docs/design_decisions.md` の配線リストを読み、今回いじる箇所がそこに載っている配線か確認する。** 載っていたら「変えると壊れる／なぜ守る」を読み、その配線を壊す変更でないか point-check する（例：敵 regen を「発動しないから無駄」と消そうとしていないか）。壊すなら押し切らず、ユーザーに「この配線に触れます」と告げてから動く
- `docs/unit_spec.md` / `docs/enemy_spec.md` / `docs/battle_spec.md` の該当箇所を読む
- **バランスは構造から逆算する。** シムを緑にするためにステを突かない。「何周持たせる戦いか」を先に決めて HP/ATK を逆算する
- **味方ステータスも敵ステータスと同格の調整肢。** 「直近の味方リバランスは確定済みだから触らない」と勝手に凍結しない。過去に完了マークが付いていても、バランスが破綻しているなら味方側を疑ってよい。ただし味方側は職の dominance チェック・スコアレンジ（unit_spec.md）を伴う全体再検証が要るため、敵側の調整で解決できないか先に検討し、味方側に触るなら**その旨をユーザーに一言告げてから**動く（無言で両方同時に動かすと原因の切り分けができなくなる）

## 出力規律

- 応答には**集計サマリのみ**を載せる（勝率・平均ターン・分布・構成別の勝ち筋）。raw な全試行ログを応答に展開しない
- 異常が出たら単一 seed に畳んで1ケースとして調べる（洪水でなく1点デバッグ）

## 独立検算（検証エージェント）

結論（推奨数値・仕様変更案・「このバランスで OK」の判定）がまとまったら、コミット提案の前に検証エージェントで検算する：

1. Agent ツール（general-purpose）を1回起動する
2. **渡すもの：結論と参照ファイルパスのみ。** 自分の導出過程・計算メモは渡さない（アンカリング防止・先入観なしの再計算をさせるため）
3. 指示する内容：
   - 結論の数値を仕様書とコード（`character_data.gd` / 敵生成 / テスト期待値）から独立に再計算・照合する
   - 仕様書とコードの整合（定数名・値の取り残し・単位の食い違い）を確認する
   - 相違があれば file:line 付きで列挙する
4. **頻度は結論セット単位で1回。** 中間ステップごとに走らせない（トークン節約）
5. 検算が食い違ったら、自分で押し切らずに両論（自分の結論と検証側の指摘）をユーザーに提示する
