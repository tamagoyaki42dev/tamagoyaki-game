# 構造監査フロー

プロジェクト全体の構造監査の運用手順。

## 手順

1. プロジェクト全体を読む（`scripts/` / `scenes/` / 主要 `docs/`）
2. **診断のみ。この段階では変更しない**
3. 観点：Resource化 / Autoload化 / Signal化 / @export化 / シーン重複
4. 問題を「影響度 × 修正コスト」で優先づけする
5. 段階移行プランを提示する

## 独立検算（検証エージェント）

報告前に、上位の指摘（目安：上位3件）を検証エージェントで実在確認する：

1. Agent ツール（general-purpose）を1回起動する
2. **渡すもの：指摘の内容と対象ファイルパスのみ。** 診断の経緯は渡さない
3. 指示する内容：各指摘が現行コードに実在するかを file:line の根拠付きで確認する
4. 実在しなかった指摘は報告から落とす。グレーだったものはその旨を添えて報告する
