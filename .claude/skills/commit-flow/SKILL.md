# コミット・SNS投稿フロー

コミット前に以下を順番に確認・更新してからコミットメッセージ案を提案する：

0. **コミット前チェック（この確認なしにコミットメッセージを提案しない）**
   - **GUT フルランを私自身が実行する**（ユーザーに聞かない）
     - コマンド: `"/c/Users/djbsh/Downloads/Godot_v4.6.3-stable_win64.exe/Godot_v4.6.3-stable_win64_console.exe" --headless --path . -s addons/gut/gut_cmdln.gd -gdir=res://tests/ -gexit`
     - 全 Pass を確認してから次へ進む。Fail があれば先にユーザーに報告して修正する
   - 以下の2つは**視覚変化・ゲームプレイ変化があるコミットのみ**ユーザーに確認する：
     - 「`docs/visual_test_checklist.md` の全項目を確認しましたか？」
     - 「1戦を通してプレイし、不自然な挙動がないことを確認しましたか？」
   → 上記が完了してからコミットメッセージを提案する

1. **`devlog/今日の日付.md`** — その日の作業内容・決定・noteネタを記録する（次タスクは backlog に集約。ここに複製しない）
2. **`docs/backlog.md`** — 最終整合の確認（追加・完了は作業中に随時反映済みのはず。漏れがあればここで直す。詳細は CLAUDE.md「タスク管理」参照）
3. **`docs/battle_spec.md` / `docs/enemy_spec.md` / `docs/unit_spec.md`** — 今回の実装・決定で仕様書と乖離が生じていないか確認・更新
4. **`README.md`** — 技術スタック・プレイ環境が実態と一致しているか確認・修正
5. **`CLAUDE.md`** — 設計方針の変更が反映されているか確認・修正

編集したファイルは必ず読み直して構造が壊れていないか確認してからコミットメッセージ案を提案する。

## SNS投稿の判断ルール（私が自動で判断する）

**投稿する**：新機能・画面追加 / ゲーム動作が変わるバグ修正 / ビジュアル変化

**投稿しない**（`[skip-sns]` を付ける）：ドキュメント更新 / 設定変更 / リファクタリング / インフラ整備 / 軽微な仕様修正

投稿する場合はコミットメッセージがそのまま X・Bluesky への投稿文になるため、SNS映えする文体（日本語・絵文字なし・ハッシュタグはスクリプトが付ける）で書く。

投稿の詳細制約（280字以内・スクショ必須・アカウント一覧）は `docs/sns_workflow.md` を参照。

## 定期整理フロー

演出・機能のひと区切りごと（バックログの演出エフェクト欄が空になったタイミングなど）に実施する：

1. `/simplify` — 重複・複雑化を圧縮する
2. `/code-review` — 整理後にバグ・問題が残っていないか確認する（**自動実行しない。推奨タイミングを提案してユーザーが判断する**）

### `/code-review` 推奨タイミング（私が提案する基準）

以下が重なったときに「`/code-review` を実行しますか？」と提案する：

- `await` / Signal / タイマー連鎖を含む変更が入ったコミットが2件以上積まれた
- 戦闘ロジック（ダメージ計算・フェーズ制御・勝敗判定）に触れた
- `/simplify` を実行した直後

**リネーム・@export追加・const抽出・ドキュメント更新のみのコミットは対象外。**
